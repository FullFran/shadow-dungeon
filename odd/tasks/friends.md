# Friends

Objective: add friends by a code and join the room they are in. Branch `feat/friends`. Delivery: server and client as separate commits. Runners: `npx vitest run --testTimeout=30000`, `go test ./...` in `server/`, real browsers over a local server binary.

## Specs

- S1 Friends need an account: a guest sees a short line saying so, with the way to the account screen. (assumption by the parent)
- S2 Each account has a short, stable friend code, generated by the server, unique, from the readable alphabet of `src/net/room-code.ts`, 8 characters, shown in the monospace code style. Emails are never used, shown or searchable.
- S3 Add by code: a request the other accepts or declines. Friendship is mutual; either can remove it. No self-add, no duplicate requests, nothing told beyond what is needed. Two crossed requests become a friendship. Caps of 50 friends and 50 pending, and a rate limit rule on sending.
- S4 Friends window, one step from the town menu and from Options on the title: your code (with copy), add by code, requests to accept or decline, your friends with nickname and state, remove.
- S5 A friend shows as offline, online, or in a room; in a room there is "Unirse", which joins through `openLobby` and `normalizeRoomCode` with all their checks. A player in a room publishes its room code only to accepted friends. Heartbeat every 60 s while signed in with the tab visible, online means seen in the last 3 minutes, cleared on leaving the room. Signed out makes no new requests.
- S6 Server: guarded routes under `/api/sd/friends` behind `apis.RequireAuth("users")`, explicit projection, new collections with every API rule nil, additive migration with up and down, account deletion cascades, answers never carry an email or an IP, a malformed or unknown code gets the same refusal, fail closed.
- S7 Client layers: `src/adapters/friends-api.ts`, `src/app/friends-screen.ts`, wiring in `src/app/main.ts`. Typed text is shown as text; nicknames go through the existing sanitising. Logging out or changing account closes the window and stops the heartbeat.
- S8 A plain line in the window says friends see your nickname, whether you are online, and your room code while in a room.
- S9 Pending, not dropped: invitations pushed to a friend, chat, blocking beyond removing, friends for guests, seeing what a friend is playing.
- Assumption (code on existing accounts): lazily, the first time an account opens the window. The migration touches no existing row, and an account that never uses friends stores nothing.
- Assumption (presence): a signed-in account with no friends and no card stores nothing; its heartbeat is answered and dropped. A signed-in solo player still sends the heartbeat (S5 "while the game is open and signed in"); a guest never does.
- Assumption (hidden tab): in a room the heartbeat also runs with the tab hidden, because a host waiting for friends on a chat is the main case and would otherwise read as offline after 3 minutes. Out of a room it stops when hidden, as S5 says.
