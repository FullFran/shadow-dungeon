# progress-continuity

## Objective
Prove that a player who played before 2026-10-26's releases keeps every bit of progress through today's save changes (v2 -> v3 -> v4, cloud sync), and credit achievements for progress made before achievements existed.

## Problem
The owner played on the builds deployed before today ("revisa que funcionen bien los logros y que no haya perdido cosas"). Today's main changed the save three times and wrapped it in cloud sync; achievements are only evaluated at run end and when the gacha or evolve windows close, so clears, Sima depth and collection made before they existed are not credited.

## Why
Owner request, 2026-10-26.

## Scope
- Continuity audit: fixtures of the real localStorage of the deployed builds (save v2 at b90c45a, save v3 at 245f309) generated by running those builds' own writers, loaded through today's code paths.
- Retroactive achievements: on load, unlock silently what persisted state proves (records: clears per dungeon and tier; records and Sima leaderboard: depth; save: collection, evolutions, awakenings, shinies, lifetime Pokémonedas), with one summary toast.
- Every achievement unlockable through a real code path; run-end wiring in solo and as a co-op guest.

## Constraints
- Allowed surfaces: src/**, tests/**, docs/gdd.md, odd/tasks/progress-continuity.md.
- No network, no production, no push. One Conventional Commit per fix, explicit paths, no AI attribution.

## Decisions
- 2026-10-26: retroactive unlocks pay their Pokémonedas once (the same settle path as any unlock: the id is stored, so a later load never pays it again).
- 2026-10-26: a pre-v4 save has no lifetime count; it is backfilled with a lower bound (balance plus what upgrades, tutor moves and Mejoras cost), never lowered.
- 2026-10-26: only rules derivable from persisted state are retroactive; flawless guardian, clear-with-species, co-op clear and the hidden stumble need a run report and stay run-only.

## Delivery strategy
single branch `fix/progress-continuity`, one commit per task; forecast ~500 authored lines; PR slicing is the user's decision.
